# tests/ —— 测试用例说明

本目录是 `word_diff` 的测试套件，设计目标与任务书一致：
**"用户的自然语言 + 若干需要比对的文档 → 结构化结果"** 这条链路能被自动验证。

## 一、怎么跑

在**项目根目录**执行（三种方式，跑的是同一批用例）：

```bash
# 1) 装了 pytest（推荐，失败信息更详细）
python -m pytest tests -q

# 2) 没装 pytest 也能跑（只用标准库的兜底运行器）
python tests/run_tests.py

# 3) 只跑某一个文件
python tests/run_tests.py diff_engine
```

可选：用**你自己的真实文档**再跑一遍（把路径放环境变量，不写进代码）：

```powershell
$env:WORD_DIFF_REAL_DOC1="D:\...\v1.docx"
$env:WORD_DIFF_REAL_DOC2="D:\...\v2.docx"
python tests/run_tests.py real_documents
```

未设置环境变量时这组用例自动 **SKIP**，换设备也不会失败。

## 二、文件清单（各自做什么）

| 文件 | 层次 | 用例数 | 做什么 |
|---|---|---|---|
| `conftest.py` | 配置 | — | 把项目根加入 `sys.path`（项目根 = `tests/` 的上一级，**不写死绝对路径**） |
| `helpers.py` | 工具 | — | 造 `.docx` / 生成最小 PNG / 进程内跑 CLI / 独立跑入口脚本；缺 python-docx 时统一跳过 |
| `nl_cases.py` | 数据 | 11 条 | **自然语言用例表**：大白话 + 应映射的 CLI 参数 + 断言名。加用例只加一行 |
| `test_diff_engine.py` | 单元层 | 17 | 核心 diff 引擎，**不依赖 python-docx**：新增/删除/修改、空段过滤与段落号保留、相似度阈值上下、重复段落、超长段落、位置保序、摘要自洽 |
| `test_docx_reader.py` | 集成层 | 8 | 读取层与路径校验：空段过滤与 index 保留、元信息、四条异常分类（不存在/不是文件/后缀不对/正常） |
| `test_cli_intents.py` | **意图层** | 5（内含 11 条 NL） | 自然语言 → 命令 → 结果契约；另有：同文档判"一致"、`--keep-empty` 生效、**入口脚本可独立运行**、`--version` |
| `test_advanced.py` | 进阶层 | 9 | 格式变化与 `char_range`、**插入段落不再导致格式漏报**（回归）、run 切分不误报、空段落/全角空格、批注、图片同/异 |
| `test_cli_errors.py` | 异常层 | 8 | 统一错误契约：`file_not_found` / `invalid_format` / `runtime_error`、退出码、参数不足、同文件、空文档 |
| `test_real_documents.py` | 可选 | 3 | 用环境变量指定的真实文档跑基础/进阶/摘要三条链路 |
| `run_tests.py` | 运行器 | — | 不依赖 pytest 的兜底运行器（收集同目录 `test_*.py`） |

合计：**50 个用例**（其中 3 个真实文档用例默认 SKIP；1 个用例内含 11 条自然语言子用例）。

## 三、覆盖的 3 类自然语言意图（`nl_cases.py`）

| 意图 | 用户会说的话（示例） | 应映射到的参数 |
|---|---|---|
| 意图1 对比差异 | "帮我对比一下 v1.docx 和 v2.docx，看改了哪些内容" / "哪些段落被删掉了" / "新增了哪些段落" / "哪几段被改写了" | 默认（结构化 JSON） |
| 意图2 生成摘要 | "总结一下主要改动" / "结果别太长，一句话结论" / "输出缩进一下" | `--summary` / `--pretty` |
| 意图3 追问详情 | "v2 里哪几个字被加粗了" / "是不是多插了空行" / "有没有新增的批注" / "图片有变化吗" | `--advanced` |

**为什么这条链路要分两半验证：**

* **工具侧**（本目录可自动断言）：给定参数，工具返回的结构化结果是否正确；
* **智能体侧**（验收时人工验证）：教师说出同一句大白话时，智能体是否选中同一个命令。
  验证办法就是把 `nl_cases.py` 里的 `nl` 原话发给智能体，看返回的 JSON 是否满足同一组断言。

## 四、设计约定（为"换设备也能跑"）

1. **不写死任何机器路径**：项目根由 `tests/` 的位置推导；需要外部文件时用环境变量 + 自动跳过。
2. **不污染项目目录**：所有临时 `.docx`、PNG 都建在系统临时目录，测试结束自动清理。
3. **缺依赖跳过而非报错**：没装 python-docx 时，相关用例 SKIP，单元层仍能全跑。
4. **同一批用例、两种运行器**：只用普通 `assert`，因此 `pytest` 与 `run_tests.py` 都能跑。
5. **素材自生成**：演示文档与图片由 `helpers.py` 现场生成（免去提交二进制测试资源）。
6. **每个文件只测一层**，失败时一眼能定位是"引擎逻辑"还是"读取/输出/进阶分析"。

## 五、怎么加你自己的用例

* **加一条自然语言用例**：在 `nl_cases.py` 的表里加一行（`nl` / `args` / `checks`），断言名从文件头注释里挑。
* **加引擎边界用例**：在 `test_diff_engine.py` 里加一个 `test_*` 函数，直接构造 `ParagraphEntry` 列表。
* **加带文档的用例**：用 `helpers.make_docx(path, blocks)` 造文档（`blocks` 支持多 run 格式与批注）。
* **加你自己的真实文档回归**：设置 `WORD_DIFF_REAL_DOC1/2` 环境变量即可复用 `test_real_documents.py`。

## 六、与任务书评分点的对应

| 任务书要求 | 本套件的位置 |
|---|---|
| ≥3 类自然语言意图 | `nl_cases.py` + `test_cli_intents.py` |
| 底层 Script/CLI 可独立运行 | `test_standalone_scripts_run_without_agent`（子进程跑两个入口脚本） |
| ≥5～10 个测试用例，含正常/边界/异常 | 50 个用例，分 5 层（正常 / 边界 / 异常各有归属） |
| 低 Token（不把全文塞回上下文） | `summary_only_low_token` 断言 `--summary` 只返回 4 个键 |
| 异常处理 | `test_cli_errors.py`（统一错误契约 + 退出码） |
| 可复现的运行环境 | 不写死路径、素材自生成、环境变量注入真实文档 |
